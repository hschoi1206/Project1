# 체중·허리둘레 기록 앱 설계

작성일: 2026-11-26 · 상태: 초안 (승인 전)

## 1. 목적과 배경

- 지금 쓰는 체중 기록 앱("databody" 백업 형식)은 광고가 많아서 쓰기 불편하다. 광고 없는 앱을 직접 만들어 대신 쓴다.
- 기록하는 것은 **일별 체중**과 **허리둘레** 두 가지다. 기존 앱에서는 허리둘레를 메모 칸에 숫자로 적어 왔다.
- 사용자는 본인과 친구들이다. 각자 Android Chrome에서 앱을 설치해 쓰고, 데이터는 각자 폰에만 저장한다.
- 다이어트 주사(위고비/마운자로) 투약자는 투약 시작일 이후의 체중 변화율을 임상시험 결과와 비교해 볼 수 있다.
- 참고 사례: 같은 계정의 `vive_coding_study/cycle` 생리주기 앱. 구조, 저장 방식, 배포 방식을 그대로 따른다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 체중과 허리둘레를 날짜별로 빠르게 입력하고 수정할 수 있다.
- 일간·주간·월간 추이와 이동평균을 그래프로 보고, 두 손가락으로 기간을 확대·축소할 수 있다.
- 체중과 허리둘레의 관계를 상관도표로 본다.
- 기존 앱 백업(`.databody`)을 불러오고, 같은 형식으로 내보낸다.
- 투약자는 임상 결과(투약군·위약군)와 자신의 변화율을 비교한다.
- 설치 후 오프라인에서도 동작한다.

**비목표 (이번에 만들지 않음)**
- 식단, 물 섭취, 운동, 음주 기록
- 칼로리·기초대사량 계산, 주간 통계 표
- 서버, 로그인, 기기 간 동기화
- 투약 용량 입력과 용량별 비교
- 알림, 목표 체중 설정

**반목표 (기능이 돌아가더라도 이렇게 되면 실패)**
- 광고나 외부 추적 코드가 들어간다.
- 기록 데이터가 폰 밖(서버, 외부 서비스)으로 나간다.
- 백업을 불러올 때 체중 기록이 조용히 빠지거나 바뀐다.
- 개인 데이터(백업 파일 등)가 공개 저장소에 커밋된다.

## 3. 제약

- **Project1은 공개 저장소다.** 코드만 올리고 사용자 데이터는 올리지 않는다. 테스트용 실제 백업 파일도 커밋하지 않는다.
- **대상 환경:** Android Chrome, 세로 모드 휴대폰 화면. PC 브라우저에서도 열리면 좋지만 최적화 대상은 아니다.
- **배포:** GitHub Pages (`main` 브랜치). 앱 주소는 `https://hschoi1206.github.io/Project1/weight/`. Pages 활성화는 사용자가 저장소 설정에서 직접 한다.
- **데이터 규모:** 기존 백업 기준 약 1,750일치. JSON으로 약 100KB라 `localStorage` 한도(약 5MB) 안에 들어간다.
- **외부 의존성 없음:** 그래프 라이브러리나 빌드 도구를 쓰지 않는다.

## 4. 접근 방식

| 방식 | 구성 | 장단점 |
|---|---|---|
| **A. 생리주기 앱과 같은 구조 (채택)** | HTML + 바닐라 JS, SVG로 그래프 직접 작성, `localStorage`, `manifest.json` + `sw.js` | 이미 검증된 구조이고 확대·축소 코드를 재사용할 수 있다. 외부 의존성이 없다. 그래프 종류는 직접 구현해야 한다. |
| B. A + Chart.js | A에 그래프 라이브러리 추가 | 차트 추가가 빠르지만 파일이 수백 KB 늘고, 확대·축소에 플러그인이 필요하다. |
| C. React 등 프레임워크 + 빌드 | 빌드 후 GitHub Actions로 배포 | 이 규모에는 과하다. 수정할 때마다 빌드해야 한다. |

사용자가 A를 선택했다. 그래프가 선·막대·산점도 수준이라 직접 그려도 충분하다.

## 5. 화면 구성

하단 탭은 5개다: **홈 · 기록 · 차트 · 투약 비교 · 내 정보**. 투약 비교 탭은 내 정보에서 투약 토글을 켠 경우에만 보인다.

### 5.1 홈
- 날짜 선택(기본값 오늘), 체중(kg, 소수 1자리), 허리둘레(cm, 소수 1자리), 메모 입력. 체중과 허리둘레는 각각 선택 입력이다. 둘 다 비어 있으면 저장하지 않는다.
- 같은 날짜에 이미 기록이 있으면 그 값을 불러와 수정한다. 날짜당 기록은 1건이다.
- 최근 체중과 7일/30일/365일 증감. 기존 앱 홈에 있던 정보라 남긴다. *(작성자 판단)*

### 5.2 기록
- 날짜 역순 목록: 날짜(요일), 체중, 허리둘레, 메모
- 항목을 탭하면 수정·삭제할 수 있다.

### 5.3 차트
상단 구분 버튼: **일간 · 주간 · 월간 · 상관**. 일간·주간·월간에는 **체중 / 허리둘레** 전환 버튼이 있다.

| 보기 | 기본 데이터 | 겹치는 평균선 |
|---|---|---|
| 일간 | 일별 실측값 | 7일 평균 |
| 주간 | 주별 평균 | 5주 평균, 20주 평균 |
| 월간 | 월별 평균 | 5개월 평균, 20개월 평균 |

- **주 구분:** 일요일~토요일. 기존 앱과 같은 기준이다. *(작성자 판단)*
- **평균 계산:** 기록이 있는 날만 평균에 넣는다. 7일 평균은 최근 7일(달력 기준) 안의 기록 평균이다. 5주·20주·5개월·20개월 평균은 해당 개수만큼의 주별·월별 평균을 단순 평균한다. 구간 안에 기록이 하나도 없으면 그 점은 비운다. *(작성자 판단)*
- **확대·축소:** 두 손가락으로 가로축(기간)을 조절하고, 한 손가락으로 좌우 이동한다. 두 번 탭하면 전체 보기로 돌아간다. 세로축은 화면에 보이는 구간의 값에 맞춰 자동 조정한다. `cycle/index.html`의 pointer 이벤트 구현을 가져다 쓴다.
- **값 확인:** 선을 탭하면 그 날짜(또는 주·월)의 값이 표시된다.
- **처음 보이는 기간:** 일간은 최근 3개월, 주간은 최근 1년, 월간은 전체. *(작성자 판단)*

**상관(체중–허리둘레 산점도)**
- 체중과 허리둘레가 **같은 날 모두 있는 기록**만 점으로 찍는다. 가로축은 체중, 세로축은 허리둘레다. 기존 데이터로 318개 점이 나온다.
- 점 색은 날짜에 따라 옅은 색(과거)에서 진한 색(최근)으로 바뀐다. 감량 경로가 보이게 하기 위해서다.
- 회귀 직선과 함께 **상관계수 r**, **기울기(체중 1kg당 허리둘레 변화 cm)**, 점 개수를 표시한다.
- 기간 선택은 **전체 / 최근 1년** 두 가지다. *(작성자 판단)*
- 점을 탭하면 날짜와 두 값이 표시된다. 확대·축소는 넣지 않는다.

### 5.4 투약 비교
- **기준일:** 내 정보에 입력한 투약 시작일. **기준 체중**은 시작일의 체중이고, 그날 기록이 없으면 시작일 이전 14일 안의 가장 최근 기록을 쓴다. 그것도 없으면 "시작일 무렵 체중 기록이 필요합니다"라는 안내만 보여 준다. *(작성자 판단)*
- **그래프:** 가로축은 시작 후 경과 주(소수점), 세로축은 기준 체중 대비 변화율(%)이다.
  - 나: 일별 실측 변화율 (점과 선)
  - 위고비 선택 시: STEP 1 세마글루타이드 2.4mg 평균, 위약군 평균
  - 마운자로 선택 시: SURMOUNT-1 고용량(15mg) 평균, 저용량(5mg) 평균, 위약군 평균
- **보기 전환:** "전체 기간"(임상 68주/72주 전체)과 "내 구간 확대"(내 기록 마지막 주차까지).
- **요약 카드:** 나(현재 변화율, kg 변화, 현재 체중). 그리고 각 참고 곡선의 같은 주차 값을 카드로 보여 준다. 위고비는 투약군·위약군 2장, 마운자로는 고용량·저용량·위약군 3장이다.
- **안내 문구:** "임상시험 평균과의 참고 비교이며 의학적 판단 근거가 아닙니다. 임상 중간 주차 값은 논문 그래프에서 읽은 근사값입니다."
- **용량 입력 없음:** 사용자 요청에 따름. 임상 곡선 자체가 증량 기간을 포함하므로 증량 중인 사용자와 비교하는 데 무리가 없다(9절 참고).

### 5.5 내 정보
- 키(cm), 생년월일, 성별 입력. 나이는 생년월일로 계산해 표시한다.
- **BMI:** 가장 최근 체중과 키로 계산하고 대한비만학회 기준으로 분류한다. 18.5 미만 저체중, 18.5–22.9 정상, 23–24.9 비만 전단계, 25–29.9 1단계 비만, 30–34.9 2단계 비만, 35 이상 3단계 비만.
- **투약 설정:** "다이어트 주사(위고비/마운자로) 투약 중인가요?" 토글. 켜면 약 종류(위고비/마운자로)와 투약 시작일을 입력한다.
- **백업:** `.databody` 불러오기(합치기/교체 선택), `.databody` 내보내기.

### 5.6 디자인
- 어두운 테마를 기본으로 한다. 사용자가 기존 앱을 어두운 테마로 써 왔다. *(작성자 판단)*
- 세부 디자인은 구현 시 `frontend-design` 스킬을 적용한다. 기존 앱의 모양을 그대로 베끼지 않는다.

## 6. 데이터

### 6.1 저장 구조
`localStorage` 키 `weightTracker.v1`:
```json
{
  "version": 1,
  "records": [
    {"id": "uuid", "date": "2026-11-26", "weight": 76.9, "waist": 81.0, "memo": ""}
  ],
  "profile": {
    "heightCm": 171.0, "birthDate": "YYYY-MM-DD", "sex": "male|female",
    "glp1": {"enabled": true, "drug": "wegovy|mounjaro", "startDate": "2026-09-27"}
  }
}
```
- `weight`와 `waist`는 없으면 `null`이다.
- 처음 실행할 때 `navigator.storage.persist()`를 요청해서, 브라우저가 저장소를 자동으로 지울 가능성을 줄인다.

### 6.2 `.databody` 불러오기
파일 형식: gzip 압축 JSON(`formatVersion: 1`, `app: "databody"`). 브라우저 내장 `DecompressionStream('gzip')`으로 푼다.

| 원본 | 변환 |
|---|---|
| `weights[].date` | `date` |
| `weights[].weightInKg` | `weight` (`null` 허용. `unit`이 `null`인 기록은 `weightInKg`도 `null`임을 확인함) |
| `weights[].memo`가 숫자만(`^\d{2,3}(\.\d+)?$`)이고 50–150 범위 | `waist` |
| `숫자 / 글자` 형태의 메모 (예: `81.0 / 혼술`, 이 앱이 내보낸 형식) | 앞 숫자는 `waist`, `/` 뒤는 `memo` |
| 그 밖의 메모 (예: `77 5`) | 손대지 않고 `memo`로 남김. 추측해서 고치지 않는다. |
| `weights[].id` | `id` (내보낼 때 같은 id를 유지) |
| `settings.height_cm`, `birth_date`, `gender` | `profile`이 비어 있을 때만 채움 |
| `diets`, `habitRecords`, `exercises` 등 나머지 | 버림 |

- 체중·허리둘레·메모가 모두 없는 기록은 건너뛴다.
- **날짜 중복:** 실제 백업에는 같은 날짜가 두 번 나오는 기록이 없다(1,752건 모두 날짜가 다름). 다른 파일에서 중복이 나오면 `updatedAt`이 가장 최근인 항목을 쓰고, 버린 건수를 불러오기 결과에 표시한다. *(작성자 판단)*
- **합치기:** 같은 날짜가 있으면 항목별로 합친다. 파일에 값이 있는 칸(체중·허리둘레·메모)만 덮어쓰고, 파일에 없는 칸은 폰에 있던 값을 유지한다. **교체:** 기존 기록을 모두 지우고 파일 내용으로 바꾼다. *(작성자 판단)*
- 불러온 뒤 "체중 N건, 허리둘레 M건, 메모 K건을 불러왔습니다"처럼 건수를 보여 준다.
- 실제 백업 파일 기준 기대값: 2020-05-05 ~ 2026-11-26, 체중 1,654건, 허리둘레 320건.
- **원본 형식 확인 결과:** `id`는 UUID v4 문자열, `timestamp`·`updatedAt`·`exportedAt`은 ms 단위 정수, `gender`는 `"male"` 같은 문자열, `height_cm`은 `"171.0"` 같은 문자열, `birth_date`는 `"YYYY-MM-DD"` 문자열이다. 새로 만드는 기록의 `id`도 UUID v4(`crypto.randomUUID()`)로 만든다.
- **테스트용 원본 파일:** 사용자가 이 세션에 올린 백업을 세션 임시 폴더에 풀어 두었다. 세션이 끝나면 사라지므로, 다른 세션에서 구현할 때는 사용자에게 다시 올려 달라고 요청한다.

### 6.3 `.databody` 내보내기
- 같은 최상위 구조(`formatVersion`, `app: "databody"`, `exportedAt`, `appVersion: null`, `weights`, 나머지 배열은 빈 배열, `settings`)를 gzip으로 압축해 `YYYY-MM-DD_HHmm.databody` 파일로 저장한다. 압축은 `CompressionStream('gzip')`을 쓴다.
- `weights[]` 각 항목: `id`, `weight`, `unit: "kg"`(체중이 없으면 `null`), `weightInKg`, `timestamp`(해당 날짜 00:00 Asia/Seoul의 ms), `timeZoneId: "Asia/Seoul"`, `date`, `memo`, `source: "manual"`, `externalId: null`, `externalSourceApp: null`, `updatedAt`.
- `memo`: 허리둘레만 있으면 그 숫자(`"81.0"`), 메모만 있으면 메모, 둘 다 있으면 `"81.0 / 메모"`.
- `settings`: `weight_unit: "kg"`, `height_unit: "cm"`, `height_cm`, `birth_date`, `gender`.
- **확인 필요:** 기존 앱이 이 파일을 받아들이는지는 개발 환경에서 시험할 수 없다. 사용자가 폰에서 한 번 확인한다. 기존 앱에 넣으면 음주·식단 기록은 빠진 상태가 된다는 점을 내보내기 화면에 안내한다.
- **필수 조건:** 내보낸 파일을 이 앱으로 다시 불러오면 원래 기록과 같아야 한다(왕복 동일성).
- **알려진 예외:** 허리둘레 없이 메모가 숫자만인 기록(예: 메모 `81`)은 다시 불러오면 허리둘레로 읽힌다. 기존 앱 형식이 허리둘레를 메모 숫자로 저장하기 때문에 피할 수 없다. 메모 입력칸에 숫자만 넣으면 "허리둘레 칸에 입력하세요"라고 안내한다. *(작성자 판단)*

## 7. 임상 참고 데이터

| 약 | 시험 | 비교 대상 | 최종 시점 평균 변화율 |
|---|---|---|---|
| 위고비 | STEP 1 (Wilding et al., NEJM 2021) | 세마글루타이드 2.4mg / 위약 | 68주: −14.9% / −2.4% |
| 마운자로 | SURMOUNT-1 (Jastreboff et al., NEJM 2022) | 티르제파타이드 15mg / 5mg / 위약 | 72주: −20.9% / −15.0% / −3.1% |

- 최종값은 논문 본문 수치(치료정책 추정치)를 쓴다. 중간 주차 값은 논문의 시간별 변화율 그림에서 읽은 근사값이다.
- 그림이 다른 추정 방식(관측값 등)을 쓰고 있어 마지막 점이 본문 최종값과 다르면, 곡선 모양은 그림을 따르고 마지막 점은 본문 최종값에 맞춘다. 화면에는 최종값을 표시한다. *(작성자 판단)*
- 중간 주차 값 조사는 구현자(Claude)가 논문·허가 문서를 찾아 수행하고, 사용한 출처와 읽은 값을 `core.js` 주석에 남긴다. 사용자는 PR 검토 때 확인한다.
- 데이터는 `core.js` 안에 `[주차, 변화율]` 배열 상수로 넣고, 출처와 "근사값" 주석을 단다. 주차 사이 값은 선형 보간한다.
- 구현 시 논문 원문과 최종값을 다시 대조한다.

## 8. 파일 구성과 배포

```
Project1/
└── weight/
    ├── index.html     # 화면, 그래프 그리기, 이벤트
    ├── core.js        # 순수 계산: 집계, 이동평균, 회귀, BMI, 임상 보간, .databody 변환
    ├── manifest.json  # 설치 정보 (이름, 아이콘, standalone, portrait)
    ├── sw.js          # 오프라인 캐시 (cycle/sw.js 방식)
    ├── icons/         # 192, 512, maskable 512
    ├── tests/         # core.js 테스트 (node --test), 합성 데이터만 사용
    └── README.md      # 기능, 데이터 저장 위치, 설치 방법
```
- 생리주기 앱과 달리 계산 로직을 `core.js`로 분리한다. 브라우저와 Node 테스트에서 같은 코드를 쓰기 위해서다.
- 배포: `main` 병합 → GitHub Pages → 폰 Chrome에서 주소를 열고 메뉴 ⋮ → **앱 설치**. 친구에게는 주소만 공유한다.
- 앱을 업데이트할 때 `sw.js`의 캐시 이름을 바꿔서 새 버전이 반영되게 한다.

## 9. 사용자 요청에 대한 검토 의견

- **상관도표를 별도 탭으로:** 날짜와 무관한 그래프라 일반 추이 그래프와 분리하는 데 동의한다. 다만 하단 탭이 6개가 되면 휴대폰에서 좁아지므로, 차트 탭 안의 네 번째 보기("상관")로 둔다. 상관도표에서 가장 쓸모 있는 숫자는 기울기(체중 1kg당 허리둘레 cm)라서 함께 표시한다.
- **키·나이·성별 입력:** BMI에는 키와 체중만 쓴다. 나이와 성별은 현재 화면에 표시만 하고 계산에는 쓰지 않는다. 나이는 매년 바뀌므로 숫자 대신 생년월일로 받는다. 기존 백업에 생년월일이 있어서 불러오기로 자동으로 채워진다. BMI 분류는 한국 기준(대한비만학회)을 쓴다. 기존 앱은 BMI 26.3을 "과체중"으로 표시했지만, 한국 기준으로는 1단계 비만이다.
- **용량 입력 제거:** 동의한다. STEP 1은 16주에 걸쳐 2.4mg까지 증량했고, SURMOUNT-1도 2.5mg에서 시작해 4주마다 2.5mg씩 올렸다(5mg군은 4주차, 15mg군은 20주차에 유지 용량 도달). 즉 임상 평균 곡선에 증량 기간이 이미 들어 있어서, 증량 중인 사용자를 그대로 비교해도 된다. 마운자로는 고용량(15mg)과 저용량(5mg) 곡선을 둘 다 그리면 10mg 사용자도 그 사이에서 위치를 가늠할 수 있다.
- **위약군 곡선:** 두 약 모두 표시한다. 임상 참여자도 식단·운동 상담을 받았으므로, 위약군 곡선은 "약 없이 생활 습관만 바꾼 경우"의 기준선 역할을 한다.
